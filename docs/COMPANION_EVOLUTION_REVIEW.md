## 执行中作出的取舍（按顺序）

| 决定与依据 | 错误时的成本／当前边界 |
|---|---|
| 沿用已批准的独立公开开发目录与分支；常驻运行目录独立 | 若隔离判断有误，合并前仍需另行分支整理；本轮未改主分支 |
| 初期保留明确的目标依赖跳过，最终恢复既定工具链再完整运行 | 若工具链不可恢复，须保留构建与真实LVGL待验收；目前目标构建及143项零跳过已完成 |
| 单独协商`turn_progress`，用真实进展续设备等待时限 | 如果兼容假设有误，新端可能需回退协议；旧端不会收到未协商状态 |
| 第一轮未评判的目标、真实LVGL及硬件表现放到统一集成 | 前两项目前通过；声音和实屏仍需人参与，不能提前算通过 |
| 待机预览使用C导出的完整60秒绝对相位 | 修正短片循环跳变，代价是生成数据较大 |
| 情绪评审未操作的浏览器／目标／实屏分开验证 | 浏览器与目标现已验证，实屏手感继续pending；缺证据时不作体验结论 |
| 提取纯C阅读生命周期模块，测试真实门禁而非UI副本 | 增加一个模块，但不增加设备正文容量或帧限长 |
| 原生异步更新缺少已证实的响应关联ID，不猜测其归属 | 下一次BOOT需重建连接，可能需要连接恢复后再按一次；不能自动重交任务 |
| 多个原生item保持首次到达的稳定顺序，不虚构排序字段 | 尚无协议证据证明完成事件允许人为逆序；若实际发生，须用脱敏序列证据改进排序 |
| 真人声音、回答风格、十轮、触摸及停声时延保留人工验收 | 夜间不自动出声，本轮不能作正式声音验收声明 |
| 静态栈帧与启动高水位分开记录，不推断长时负载 | 启动状态无音频故障／丢事件；没有长时soak或链路线程运行高水位结论 |
| C与JS分席，合并检查实际TLS／LVGL边界 | 未覆盖的边界仍可能有缺陷；不把一席未判断的内容自动当作通过 |
| 首次偶发无回复根因保留未知，404／200只支持恢复策略 | 原异常可能再现，仍需阶段提示和安全恢复 |
| 远端PR与CI另行核对实际推送头 | 未完成前保持草稿，不宣称云端全项或固件构建通过 |
