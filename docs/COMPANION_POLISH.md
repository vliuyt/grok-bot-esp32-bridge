# 小糖的触摸与对话体验

2026-10-22 开发分支更新，保留经典粉色圆脸和原生 Bot。语音继续只用实体 BOOT，触屏负责陪伴、字幕与设置。

## 2026-10-23：对话节奏与情绪连续性

本轮保留现有外观、BOOT、字幕和音量，只打磨对话体验：松开后先专注等待，约3秒后轻移视线，约8秒后轻微抬头；这些动作不会伪造任务进展或改变超时。扬声器确实播放且队列排空后，保留约900ms回正与注视，期间可以立即再次按BOOT。

真正开始录音时冻结当前抚摸余韵，轻微带入聆听、思考、说话和收尾。原有60秒余韵照常衰减，不因对话续期。新一轮重新取当前状态，失败、短录音、取消和断线清理旧状态。

新固件与Mac协商`companion_mood`后，仅在BOOT请求中附带`neutral/warm`；抚摸本身不联网，不发送坐标或触摸过程，不增加历史消息。暖意只给本轮回答附加轻微措辞建议，保留完整原角色、声音、工具及用户明确要求。采用[xAI单次回答指令](https://docs.x.ai/developers/model-capabilities/audio/speech-to-speech#per-response-instructions)，真实模型效果仍由真人验收。旧端保持原方式。

201项本地检查零跳过，真实LVGL验证收尾不遮字幕、阅读页保持；C、JavaScript和整体审查通过。本轮构建、安装与人工结果见[独立验收记录](dialogue-mood-validation.json)。下文157项及旧实物反馈保留为前一轮历史。

## 怎么互动

| 操作 | 反应 |
|---|---|
| 主屏轻点圆脸 | 落指就抬眼，视线跟随触点；松手后逐渐看回来 |
| 横向抚摸 | 移动中放松眼睛，松手后保留原有情绪余韵 |
| 900ms 内轻点三次 | 温和躲一下，再看回来；慢点三次不会触发，抚摸会中断连点计数 |
| 困倦或熄屏时触摸 | 短暂伸展后回应 |
| 已就绪时按住 BOOT | 立即开始录音，松开提交；播放时按住仍会打断旧回答 |
| 未就绪时按住 BOOT | 本次只唤醒和连接，提示尚未录音；恢复后先松开，再重新按住说完整一句 |

触摸不录音、不发起云端请求，也不增加声音。上划设置、右滑返回、大字阅读和现有音量刻度继续沿用。通话和错误提示优先，触摸不会把“正在听”或“正在等”盖掉。切页、按 BOOT 或丢失触点会取消本次触摸。

## 动作如何变化

眼睛与身体按实际经过时间逐渐跟随目标姿态，减少轻点、抚摸、等待、回答结束时的突变。录音／连接文字与屏幕开关立即更新。说话幅度由实际播放电平驱动；没有新的播放电平时逐渐收动作。

首次绘制、长时间停绘或时间回退会重置过渡，避免把休眠前的动作带回新画面。状态固定容量，不为互动保存录音、触摸历史或额外设置。

## 验证边界

本地主机检查覆盖：连接恢复不续录半句、登录提示代数隔离、900／901ms 连点边界、无 MOVE 的快速抚摸、坐标／失触取消、语音优先、不同帧率下的平滑、真实 LVGL 指针操作及现有设置／阅读回归。主机检查不能代替实屏手感、真实扬声器或首次出声延迟。

157项本地检查零跳过，最终镜像已保护安装并校验读回。使用者确认轻点、抚摸和三连点自然且可区分，并听到一次清晰原生回答。唤醒伸展、说话过渡、长待机首次回复及精确时延仍未单独验收。最新构建、安装与人工确认见[本轮验收记录](companion-polish-validation.json)。此前成功的十轮语音、长回答、打断和余韵属于旧镜像，继续保留在[历史记录](companion-evolution-validation.json)，不算本轮新固件验收。

上一轮当时尚未确定待机后的原生服务错误根因。随后已完成有门禁的原会话续接和一次较长待机后的真人首答，详见[独立待机记录](idle-first-use-validation.json)。完整隔夜与重复稳定性仍单独验收，不据一次清晰回答宣称长期稳定。
