# v0.2.0 目标：更有反馈、更易阅读、更易安装

状态：v0.2.0开发中；表情与字幕模式已实现代码和无声预览，发行打包与新版实机验收仍待进行，尚未发布。基线为 v0.1.1。

## 已确定的方向

使用者认可参考 [宗主 zongzhu-bot](https://github.com/Liu-zhongxian/zongzhu-bot) 的设计思路，下一版重点为宠物表情、字幕模式、易安装的发布包。参考其表情与字幕体验、板型专用发布和教程组织方式；小糖继续使用已有 Bot 的原生语音、上下文和任务通道。

保持微雪 1.43C、经典粉色圆脸、实体 BOOT 按住录音／松开提交／再次按住打断；触屏用于互动和设置，不恢复触屏说话按钮。继续使用 Mac 常驻桥接，不引入额外 STT／TTS。夜间开发不自动播放声音。

以下细节作为实施默认值，预览时可调整。

## 一、宠物反馈

- 保留现有待机、开心、招呼、聆听、思考、说话、困倦；增加好奇、困惑两种可辨识反馈。
- 好奇用于本地轻触后的短暂回应；困惑用于语音不可用或本轮等待超时，只维持2秒，不反复表演。
- 抚摸开心维持现有1.8秒；聆听／回答优先于临时触摸反馈，困倦与断网仍可本地表现。
- 保持粉色圆脸和黑眼睛，用眼形、视线、身体轻动区分，不增加复杂菜单或声音。
- 2026-10-20 预览反馈选择“再活泼一点”：提高好奇歪头、抚摸弹跳和招呼幅度；待机、聆听与思考继续保持克制。
- 先用静音可点击预览展示全部状态，再实机核对。预览与固件共用状态参数用例，避免只实现网页效果。
- 不把倾斜／摇晃、新传感器驱动、语音唤醒词列入本版承诺。

验收：各状态在圆屏可辨认；触摸不误录音；播放结束以真实队列排空为准；断网仍可抚摸；动画不让录音／播放出现新增丢帧或音频故障。测量触摸到首个画面变化与 BOOT 到录音状态的时间，记录实测结果后设性能目标。

## 二、字幕体验

- 设置页选择「完整」「简洁」「关闭」，默认简洁。选择保存后重启仍生效；BOOT 继续专用于语音，不复用长按切字幕。
- 简洁：当前收到文本的第一句、最多两行；中英混合和 emoji 不截断 UTF-8 字符。
- 完整：查看当前收到的字幕窗口，可滚动；首版仍受现有320字节窗口限制，不宣称有整段对话历史或保证长回答全文。若要扩大文本容量，必须另行验证桥接、线协议、设备缓冲和布局后再提高发布承诺。
- 关闭：隐藏对话正文，仍显示 BOOT 指引、连接和必要错误状态；本地抚摸反馈不受影响。
- 不同模式下圆脸和文字不重叠，字幕离开圆形边缘，设置页可返回；开始新轮次或切断连接时清除旧轮次文本。
- 老配置 captions=false 对应关闭，true 对应简洁；保留现有配置结构，在独立NVS键保存模式，降级时仍能读取原配置。

验收：三模式各检查中文、英文、混合、emoji、空文本与320字节边界；重启、旧设置迁移、保存失败、断线和打断不显示错误轮次文本。连接提示不可被字幕开关隐藏。普通脱敏截图仍隐藏对话正文；布局展示用固定测试文本，不导出私人聊天。

## 三、发布与安装

- 为明确板型提供专用源码与应用镜像包：版本、提交、板型、ESP-IDF/依赖版本、应用偏移、源代码／镜像SHA-256、许可清单、构建和验收记录。
- 包含安装器需要的完整受控源码及依赖锁，使既有源代码绑定校验可继续工作；不为预编译镜像关闭校验。
- 只支持现有兼容分区及已确认ota_0，不改分区、启动器或OTA元数据。其他布局明确拒绝，不宣传任意出厂板开箱即刷。
- 升级路径：核对板型与版本 → 保存并验证私人完整备份 → 检查包与布局 → 应用槽安装 → 状态检查 → 必要时恢复。
- 不包含作者账号、Wi-Fi、配对密钥、私人备份、实际聊天或录音。提供中文步骤、Mac服务启停和排错指南。
- 可复现意味着两次干净源码构建可验证一致；如暂不能做到镜像字节一致，记录差异原因及可验证部分，不标记“可复现构建通过”。

验收：从干净目录解包可核对镜像和源码；损坏包、错板型、错误OTA状态在写入前被拒绝；保留恢复路径并验证同设备安装／恢复往返。第二台设备或全新使用者的成绩缺失时明确写入发布限制。

## 发布门槛与执行顺序

三个子计划分别实现并审查，依次为 [表情互动](../plans/2026-10-19-v0.2.0-expressions.md)、[字幕模式](../plans/2026-10-19-v0.2.0-captions.md)、[发行打包](../plans/2026-10-19-v0.2.0-release.md)。开发期间不自动刷机；实机升级沿用先备份、仅写应用槽、核对恢复办法的流程。

发布前重跑现有语音多轮、上下文、简单任务、长回答、打断及重连验收，核对原生声音；不把旧版或静音模拟成绩替代新版实机结果。现有BLE、电池及第二台设备等缺口持续跟踪，不因新界面完成而自动销项。

参考仅用于设计分析。实际复用上游代码时逐文件核对来源与许可并保留声明，不直接刷入1.75C固件。
